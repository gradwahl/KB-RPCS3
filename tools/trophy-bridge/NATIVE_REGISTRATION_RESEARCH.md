# Native PS5 trophy bridge — verified findings and next work

**Objective:** Show each PS3 game running in KB-RPCS3 as a separate trophy list in the PS5's **native**, offline Trophies menu. **Not yet achieved.** PSN sync is out of scope. **Latest live finding (2026-11-01): separate owner-test title `PPSA88395` installed, launched (PID 255), exited and unregistered successfully on 13.20.** The test app was not the emulator, and did not include or register trophies.

**Measured on Sunday 2026-11-01, firmware 13.20** using a read-only local sysctl payload, PS5 FTP, and offline host scripts. No live trophy database edits, SceShellCore patches, trophy unlocks, or PSN requests were made.

## Current facts

### 1. Firmware: verified 13.20 (previous 13.60 assumption was wrong)

- Read-only PS5 ELF payload `tools/trophy-bridge/ps5_fw_probe.c` compiled with the installed PS5 payload SDK and executed via the existing ELF loader at port 9021.
- Console reports `kern.sdk_version=0x13200006` and `kern.version=r228185/releases/13.20 Apr 16 2026 12:53:28`. The version's high bytes are **BCD** (`0x13.0x20` -> 13.20), not decimal 19.32.
- `run_firmware_probe.py` checks for a complete sentinel, consistent SDK and kernel release, and saves a local report with the ELF SHA-256.
- `KB-RPCS3/INSTALL.md` mentions a **reference development console** on 13.60; it is not the live console. RPCS3 log `Firmware 4.93` refers to emulated **PS3** firmware, not PS5.

### 2. Per-game identity: verified for both games

| PS3 game | Genuine PS3 title ID | Trophy set | Proposed PS5 tile ID |
|---|---|---|---|
| GTA IV | `NPUB30702` | `NPWR00132_00` (66 trophies, 2 DLC groups) | `PPSA88395` |
| Dead Island Riptide | `BLES01739` | `NPWR03806_00` (36 trophies) | `PPSA85381` |

- GTA IV identity is established by the game's installed `dev_hdd0/game/NPUB30702/TROPDIR/NPWR00132_00`.
- Dead Island identity is **confirmed from its actual PS3 ISO9660 contents** using `read_ps3_iso_identity_ftp.py`. Only **11,332 bytes** in six FTP ranged reads of the 3.7 GB ISO were retrieved. The disc has `PS3_GAME/PARAM.SFO` `TITLE_ID=BLES01739` and `PS3_GAME/TROPDIR/NPWR03806_00`; no filename/title guessing was needed. The `XISO33006` app-cache ID is not the original game serial.
- **Launcher process ownership is now source-confirmed:** `tools/launcher/main.c` submits a one-shot payload and returns through `catchReturnFromMain()` → `sceSystemServiceLoadExec("exit", NULL)`. `tools/launcher/launch.c` waits for the tile to exit, then invokes `sceLncUtilLaunchApp("PPSA99303", ...)` for the emulator. Thus the per-game native tile **is not alive** while the PS3 game runs; only the main `PPSA99303` app owns the running emulator context. Distinct native trophy owners need a new architecture, not just a new tile folder.
- The one already recorded KB-RPCS3 tile is `PPSA80278 NPEB00393` (another title). Both planned IDs are currently unused in the checked `/data/homebrew` and `/system_data/priv/appmeta` title inventories.
- `plan_native_title_registration.py` mirrors `app/examples/rpcs3ps5/kit/tiles.cpp`'s **CRC32(serial) % 10000** and linear probing, and checks reserved IDs to avoid collisions. The output plan has `registration_allowed=false` for both.
- **Not installed:** the planned PS5 title IDs are reservations in a PC-side plan, not console tiles. The current tile launch architecture passes the game boot key to the **shared** main title `PPSA99303`, and its distinct native trophy identity/ownership has not been proven or implemented.

### 3. Native PS5 trophy/UDS format and registration: structural prototypes work, service registration blocked

- RPCS3 `TROPCONF.SFM` and `TROPUSR.DAT` were exported read-only (102 trophies, 1 unlocked in original RPCS3 progress), preserving icons, groups and original unlock timestamp ticks in private PC files.
- An offline UCP archive builder produces a version-1 PS5-format `trophy00.ucp`, with `tropconf.json`, `tropmeta_en-US.json`, icons, file-table integrity and SHA-1, matching the public PS5 UCP sample format.
- The synthetic `build_paired_uds_prototype.py` produces matching `trophy00.ucp` and `uds00.ucp`, including hypothetical `_UnlockTrophy` events and stat IDs. GTA IV: 66 trophies / 65 synthetic non-platinum UDS rules. Dead Island Riptide: 36 trophies / 35 rules. These are experimental schema-compatible local research artifacts **not tested as accepted by a PS5**.
- Live read-only reference inspection of a legitimate existing native game `PPSA06225`: `npbind.dat` is 532 bytes, v1, `0xD294A018`, plaintext tag 0x0010 `NPWR27255_00` and sealed TLVs; its `trophy00.ucp` and `uds00.ucp` passed archive SHA-1 checks. 40/41 native trophies have UDS conditions and there are 40 corresponding trophy stat definitions and extraction rules. No sealed contents or user progress were retained.
- `inspect_existing_npbind.py` safely reports metadata **only**. A working Sony-accepted `npbind.dat` for a synthetic PS3-derived game cannot be assumed from an existing game's binding and must not be forged by copying its protected payload.
- Public `ArkSama/PS5-PHU-Trophy-System` documents register/install support **4.03–12.70**. Source `src/phu_fw_offsets.c` doesn't provide 13.20 offsets. Its documented registration flow requires active game identity, `npbind.dat`, `libSceNpTrophy2`, firmware-specific SceShellCore/NpManager patches and game/title state. The PS5's 13.20 **cannot safely use older firmware patch addresses**.
- **Native menu install remains blocked:** (a) valid matching title-specific binding, (b) verified 13.20 trophy-service integration, (c) an active distinct native PS5 process/title for each emulated game, (d) an actual RPCS3 guest-unlock-to-PS5 UDS event source. Simply copying UCP or UDS to `/user/trophy2` or `sce_sys` is not a registration.
- No native registration attempt, shellcore patch, privileged file write, game-title installation or PSN sync was performed. All generated output is kept outside Git.

### M4c — read-only 13.20 Trophy 2 library fingerprint and PS3 unlock ingestion: COMPLETE (2026-11-01)

- A new `fingerprint_native_trophy_runtime.py` queries only `/system/common/lib` over FTP, validates PS5 ELF64/PRX layouts and hashes the four relevant native system libraries in RAM. The console's 13.20 `libSceNpTrophy2.sprx` (124416 B), `libSceNpTrophy.sprx` (230220 B), `libSceNpManager.sprx` (476816 B), and `libSceIpmi.sprx` (92476 B) passed ELF and dynamic segment validation. The exact 13.20 SHA-256 values were stored in the private PC-side `native-trophy-runtime-13.20.json` report. No proprietary binary data were written to the repository, and **no native trophy APIs were called or loaded**.
- PHU `WORKFLOW.md` confirms `sceNpTrophy2RegisterContext` enters SceShellCore (NPXS40082) via IPMI, and a valid service registration requires game identity, NPWR/binding checks and storage commit. Presence of the system libraries alone **does not** prove the capability to register a synthetic list; the public patches remain firmware-specific and are not verified on 13.20.
- A new `poll_ps3_trophy_changes.py` polls only each selected game's `TROPUSR.DAT`, validates with the existing RPCS3 binary reader, and compares against the original saved PC manifest. It produces PC-local `ps3_trophy_newly_unlocked` event records when a baseline locked trophy becomes unlocked. Unknown baselines, ID mismatch, duplicate states and unexpectedly permitting a native registration operation all fail closed. Existing earned state is preserved; reversals are reported as warnings, not misinterpreted as events.
- Live poll on 2026-11-01: GTA IV 1/66 unlocked, Dead Island Riptide 0/36 unlocked; **0 new unlock events**, **0 reversed unlocks**. PC-only `read-only-trophy-poll-2026-11-01.json` saved alongside the other private research artifacts. Neither system trophy records nor RPCS3 source records were modified; PSN untouched.
- **52 offline tests PASS** across the read-only snapshot/export, PS5 UCP/UDS prototype, binary binding parser, firmware identity and ISO checks, native title planner, live state-diff logic, and 13.20 runtime fingerprint format checker.

**Remaining hard blockers:** per-game active native PS5 process identity instead of one-shot tiles; homebrew NPWR/binding acceptance; firmware 13.20-specific daemon registration implementation and exact offsets verified against the correct binaries. No safe way has yet been demonstrated for the PS5 native menu to accept these PS3-derived trophies. The read-only diff pipeline is ready as an offline source only, not a registration/unlock sink.

## Next engineering actions (in priority order)

1. Research/implement 13.20-specific, read-only trophy-service capability probing and verify exact loader/system ABI **without** writing to SceShellCore or user data. PHU's 12.70 binary offsets are not portable.
2. Prove that a per-game PS5 tile can keep a native process alive and own a trophy context despite delegating guest execution to `PPSA99303`; otherwise design a separate minimal per-game title process with its own lifecycle.
