# GTA IV NPUB30702 — current-guest-context lookup audit (2026-10-31)

**Status:** source and existing-log review only; **no source or runtime optimization**, no PS5 deployment. Follow-up to the native host TLS guest-state probe in `GTA-IV-native-TLS-guest-fastpath-feasibility-20261031.md`.

## Question

Find a repeatedly executed SPU-side C++ helper doing an expensive guest-context lookup that a *new* host native-TLS cache could replace.

**Finding: no such *hot and expensive* current-SPU-context helper is confirmed in GTA IV yet.** The clearest repeatable **current-thread** retrieval already uses native TLS; the clearest object-ID manager lookup is more expensive, but GTA IV's observed SPU layout excludes that raw-SPU path.

## Hot JIT coverage

SPU JIT C++ helpers are generally emitted with the pointer explicitly supplied: `SPULLVMRecompiler.cpp` calls `spu_exec_mfc_cmd`, `spu_read_channel`, `spu_get_events`, `spu_write_channel` and state/interrupt helpers with the `m_thread` function argument. Local-store loads/stores use `m_lsptr` directly. PPU JIT receives `m_thread` and memory base directly. In the separate PS5-target assembly probe, replacing direct arguments by a new native-TLS cache generated 9 vs 2 instructions for r13 access and 11 vs 3 for an LS byte (including returns and a null guard); this is a code-generation comparison, not measured latency/FPS.

## Conclusion and next measurement

We found a **specific repeated current-SPU-context access** (`SPUThread.cpp:6094`), and a **more expensive target-SPU object lookup** (`SPUThread.cpp:2187`). **They do not combine into a demonstrated GTA IV native-TLS optimization:** the first already uses native TLS, while the second is specific to raw SPUs, which GTA IV reported zero of.

**Recommended next step:** avoid guest-TLS changes. Under a default-off PS5 diagnostic, count/time a small, safe sample of (a) `SPUThread.cpp` lost-reservation wait-callback entries and time spent in reservation notifications/waiting; (b) `sys_event_port_send` object-manager accesses only if their call frequency in a stable outdoor GTA IV run is nonzero. Keep guest semantics and pointer lifetime intact; do not claim any bottleneck from source inspection alone. Our previous SPU MFC gate1 and FIFO-yield experiments did not demonstrate an FPS gain, so do not repeat blindly.
